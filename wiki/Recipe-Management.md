# 📋 레시피 관리 가이드 (Recipe Management)

**레시피(Recipe)**는 nRF Test Suite에서 수행할 검사 시퀀스의 단계, 순서, 각 카드의 세부 판정 기준값(Criteria), 참조 파일의 해시 정보를 표준 JSON 파일(`.recipe.json`)로 패키징한 검사 규격서입니다.

---

## 1. 레시피(Recipe) 개념 및 중요성

양산 라인이나 품질 검증에서는 "어떤 검사를 어떤 순서로, 어떤 기준값으로 실행했는가"가 절대적으로 보증되어야 합니다.
- 단순히 스테이션에 설치된 코드를 실행하는 방식은 작업자가 임의로 파라미터를 변경하거나 코드가 업데이트되었을 때 검사 이력을 역추적할 수 없습니다.
- nRF Test Suite는 **레시피 기반 검사 모델**을 채택하여, 실행되는 모든 검사의 스펙을 파일 하나로 정의하고 무결성을 암호학적으로 검증합니다.

---

## 2. 내용 지문 (Content Fingerprint)

레시피 파일 내부에는 **`fingerprint` (SHA-256 기반 16진수 해시)**가 포함됩니다.

### 지문 계산에 포함되는 항목:
1. **검사 단계의 순서 및 카드 식별자 (`module_id`)**
2. **각 카드의 모든 판정 기준값 (`criteria`)**
3. **외부 참조 파일의 해시 (예: 플래싱할 펌웨어 `.hex` 파일의 내용 SHA-256)**

> **🛡️ 위변조 방지**:
> 텍스트 편집기 등으로 레시피 파일의 기준값(예: 전압 상한값)을 임의로 수정하면 지문 불일치(`Fingerprint Mismatch`)가 감지되어 로드가 거부되거나 경고가 표시됩니다.

---

## 3. 레시피 내보내기 및 가져오기

### 1) 레시피 내보내기 (Export Recipe)
1. GUI 상에서 엔지니어 모드로 진입합니다.
2. 대시보드에 검사에 필요한 카드를 배치하고 순서와 기준값을 원하는 대로 설정합니다.
3. 상단 메뉴 `레시피(Recipe) -> 📤 레시피 내보내기 (.recipe.json)...`를 클릭합니다.
4. 레시피 이름(Name), 버전(Version), 설명 메모(Notes)를 입력하고 저장 경로를 지정합니다.
5. 저장 즉시 내용 지문이 계산되어 `.recipe.json` 파일이 생성됩니다.

### 2) 레시피 가져오기 (Import Recipe)
1. 상단 메뉴 `레시피(Recipe) -> 📥 레시피 가져오기 (.recipe.json)...`를 클릭합니다.
2. 파일을 선택하면 **사전 유효성 검사(Validation)** 다이얼로그가 표시됩니다:
   - **스키마 검증**: 지원되는 레시피 스펙 버전 확인
   - **설치 여부 확인**: 레시피에 정의된 카드가 현재 스테이션의 `cards/`에 모두 설치되어 있는지 확인
   - **외부 파일 검증**: 펌웨어 바이너리 등 참조된 파일이 실제로 존재하는지, 레시피 기록 당시와 내용이 동일한지 해시 대조
3. 검증 결과 이상이 없으면 `적용(Apply)`을 눌러 대시보드에 즉시 배치합니다.

---

## 4. 레시피 잠금 (Locked Recipe) - 양산 라인 보호

양산 현장에 레시피를 배포할 때, 작업자가 실수로 기준값을 바꾸거나 단계를 누락하는 사고를 방지하기 위해 **레시피 잠금**을 지원합니다.

- **잠금 설정**: 레시피 내보내기 시 `[v] 잠금 (운용자는 편집 불가)` 옵션을 켭니다.
- **잠긴 레시피 적용 시 동작**:
  - GUI가 자동으로 **운용자(Operator) 모드**의 제약 조건을 적용합니다.
  - 카드의 삭제 버튼(`🗑`), 설정 버튼(`⚙️`), 순서 변경 버튼(`⬆`/`⬇`)이 비활성화됩니다.
  - 팔레트에서 새 카드를 대시보드로 끌어다 놓을 수 없습니다.
  - 엔지니어 모드로 비밀번호를 입력하고 전환해야만 잠금을 해제하고 설정을 수정할 수 있습니다.
